# De-Williams Place Supermarket Attendance System

A standalone attendance web app (HTML/CSS/JavaScript) with a PHP + JSON API backend.
The frontend and API can be hosted on different domains.

## Included
- Staff check-in by selecting/entering their registered name.
- One attendance record per staff member per workday.
- Configurable opening time and grace period (admin settings).
- Late status and exact minutes late shown immediately.
- Admin dashboard: staff list, attendance log, weekly/monthly summaries, lateness frequency and CSV export.
- PHP API with JSON-file storage, file locking, basic admin authentication and CORS support.

## Requirements
- PHP 7.4+ (PHP 8+ recommended), with write permission for `data/`.
- Serve the `api/` folder from a PHP-enabled host.
- Serve `index.html` and `assets/` from any static host.

## Setup
1. Upload the `api/` folder and `data/` folder to a PHP host.
2. Ensure `data/` is writable by the PHP process.
3. Set the admin password before exposing the API:
   - Set environment variable `ATTENDANCE_ADMIN_PASSWORD` to a strong password, OR
   - Edit `api/config.php` and replace the default password hash with one generated by PHP:
     `php -r "echo password_hash('YOUR_STRONG_PASSWORD', PASSWORD_DEFAULT), PHP_EOL;"`
4. Configure allowed frontend origin(s) in `api/config.php` (`ALLOWED_ORIGINS`).
5. Upload `index.html` and `assets/` to your frontend host.
6. Set the API URL in `assets/app.js`:
   `const API_BASE = "https://your-api-domain.com/api";`
7. Open the frontend. Sign in to the Admin tab with your configured password.

## Default attendance policy
- Opening time: 08:00
- Grace period: 10 minutes
- Late status begins after the grace period. Example: 08:16 check-in = 6 minutes late.
- The admin can change both values in Settings.
- Uses the server's configured timezone. Set the PHP host timezone to `Africa/Lagos` (recommended).

## API overview
All endpoints return JSON: `{ "success": true|false, ... }`

Public:
- `GET /api/staff.php` — list active staff names for the check-in screen.
- `POST /api/attendance.php` — check in: `{ "staff_id": 1 }`

Admin (send `Authorization: Bearer <token>`):
- `POST /api/login.php` — `{ "password": "..." }`
- `GET /api/admin.php?action=dashboard`
- `GET /api/admin.php?action=staff`
- `POST /api/admin.php?action=staff` — `{ "name": "..." }`
- `DELETE /api/admin.php?action=staff&id=1`
- `GET /api/admin.php?action=attendance&from=YYYY-MM-DD&to=YYYY-MM-DD`
- `GET /api/admin.php?action=settings`
- `POST /api/admin.php?action=settings` — `{ "opening_time": "08:00", "grace_minutes": 10 }`

## Production notes
- JSON storage is suitable for a small single-location team and low traffic. For heavy concurrent usage or multiple branches, move to MySQL/PostgreSQL.
- HTTPS is required in production.
- Use a strong admin password and restrict CORS to your actual frontend origin.
- Consider adding staff PINs/QR codes if impersonation becomes a concern. Name-only check-in is convenient but cannot verify identity.
- The API stores a single daily check-in per staff member; duplicate attempts return the existing record rather than creating another.
